# Phase 10 — reconnect, match presentation and settings revision

User request: 2026-10-28. This work remains in Phase 10; the existing human visual, Android and reviewed-content gates remain open. Baseline checkpoint: b80f43a, pushed before work began.

## Order and acceptance

1. **Reproduce the scoreboard problems first.** Use the existing multi-process LAN and Godot scene probes to time reveal vote, host transition, client receipt, first render and subsequent idle. Capture host/client disconnect reasons and profiler frame times without logging tokens. Test at least two remote peers and idle beyond the reported failure, with and without a real disconnect. Fix the measured cause(s), add regressions, and measure again. Do not call a vote waiting for all connected seats a rendering delay without measuring it.
2. **Restart-safe rejoin and explicit departure.** Persist only the minimum versioned, session-bound reconnect credential and endpoint on the device using the existing persistence boundary or a focused service; never log it. On reopening, locate/verify the original live host and show a global, accessible prompt across screens, unless a new game has been created. Accept restores all device-owned slots through the existing host-authoritative token mechanism and receives current private snapshots; no replayed answer/vote/card can apply twice. Reject sends a duplicate-safe authenticated leave intent; the host permanently revokes that reservation, keeps historical results, removes the seat from active quorum, and broadcasts a distinct Left status. Keep Disconnected, Left and Connected separate in snapshots and UI everywhere relevant. Preserve pause/resume behavior and handle multiple local slots, host closure, stale session, unavailable host, replay, app termination and new-game precedence. If the host is offline, a departure cannot be visible to it until communication succeeds; persist a pending departure and do not claim it was delivered. Review transport privacy, protocol version, bounds, manual-IP compatibility, recovery and storage failure; test real restarts and packet duplication.
3. **Scoring setting.** Add host-selected speed scoring on/off to match setup and immutable Core settings; host time, not client time, remains authoritative. Existing timed behavior is retained when enabled; disabled means base/difficulty/strategy only. User confirmed 2026-10-28: default on; untimed bonus up to +10% of base, linearly decreasing to zero over 30 seconds of unpaused host time. Review difficulty, cards, confidence, tie-break, pause, score limits and protocol compatibility. Cover boundaries and malicious/duplicate inputs in Core and integration tests; document rules and version migration.
4. **Question fit.** Add persisted device preference, default on, for measuring available viewport after safe areas and fitting question and all answer text by reducing font size within readable bounds, independent of touch-target dimensions. Recalculate on resize, language, content and large-text changes; preserve labels, shapes and accessibility. If even minimum readable text cannot fit, keep an accessible scroll fallback rather than clip content or shrink targets. Test long Greek/English strings and portrait/landscape, small screens, enlarged text and preference off.
5. **Answer reveal.** Separate correct-answer heading and explanation from a clearly titled Fun Facts section with distinct accessible styling; hide the section if empty. Preserve delayed reveal, modal input isolation, localization and long-content scrolling. Verify on phone and host view.
6. **Vote indicators and setup icons.** Replace repeated vote text with recognizable continue/end icons and counts on every relevant screen, retaining accessible names, tooltips or textual equivalents. Add meaningful labelled icons to game-setting rows, using existing icon language, without sacrificing clarity for icon-only ambiguity. Verify keyboard, touch, localization, contrast and multiple local seats.
7. **Scoreboard and animation.** Create responsive top-three podium plus ordered compact list for remaining players, with ties and teams treated consistently with authoritative rankings. Show per-question changes then count from prior to authoritative total over 0.6 seconds and animate actual ranking changes. Do not derive authoritative scores on clients; define safe presentation inputs for negative deltas, transfers, bonuses, late snapshots and reconnect. Never replay an animation on repeated snapshots or block interaction. Reduced motion renders the final authoritative state immediately. Capture wide host and portrait controller views with one through eight players and ties.
8. **Device settings redesign.** Rebuild the device settings screen composition from scratch, respecting the user's replacement request while preserving working preferences, persistence, focus, privacy, translations, safe areas, back navigation and error feedback. Reuse shared QuizShowTheme, ShowtimeTheme and scene-owned ShowtimeJuice; keep approved art where it helps. Include auto-fit and a theme selector when implemented. Test every control and view in game and out, with touch, large text, high contrast and reduced motion.
9. **Extra themes — design and implementation plan.** Design three coherent optional palettes/skins in addition to the existing Showtime look: a bright studio, a midnight neon studio, and a warm retro studio. Prototype them with the shared theme assembler and existing illustrated stage assets, preserving answer identities, readable Greek, contrast and focus states. Theme is a local persisted device choice, applied immediately and independent of game authority; default remains the existing style. Validate every view and accessibility mode; avoid parallel theme/motion systems or unsupported asset claims. Final palette names and designs can be refined during visual review.
10. **Verification and delivery.** Run targeted Core, integration and GdUnit tests plus required build and local LAN regressions; run validator only if question content/schema changes. Inspect actual Godot viewport captures and record findings; test on physical Android and Windows when available. Update PRODUCT/GAME_DESIGN/NETWORK_PROTOCOL/TESTING and Phase 10 context as behavior changes, append actual evidence to build log, run git diff --check, commit and push the completed work. Report any unobserved hardware/visual gates explicitly; do not claim completion before they pass.

## Dependencies and open decisions

The scoreboard investigation precedes visual choreography so defects are measurable. Reconnect and scoring require protocol compatibility review; neither may compromise the existing privacy and authority boundaries. User confirmed default-on speed scoring with the proposed formula and a pending offline departure. LAN alone cannot inform an unreachable host of a rejection in real time. No host migration is implied. Extra themes are local visual preferences, not a shared match setting.
